---

## 1. 一句话目标

**关键写操作可追溯，一期底座收尾可交接**：审计写入起步；不引入重型中间件，除非业务强制。

---

## 2. Must（必须）— 初稿，开工前可微调

1. **审计日志写入**
   - 至少覆盖：文档上传 / 删除、KB 成员变更、登录成功/失败（可选）
   - 写入现有 `audit_log` 表；失败不阻断主流程（best-effort）  
2. **审计只读查询（最小）**
   - `GET /api/v1/audit-logs`（ADMIN）：时间倒序 + 可选 action / user 过滤  
   - 前端可先用简易表格页，或仅 API + curl 验收  

---

## 3. Should

- Citation / 会话边角体验小修  
- Golden Dataset 增加 1～2 条「检索离线断言」雏形（仍不调付费 API）  
- 系统用户创建（同 org 建 USER）若演示成员协作刚需可薄做一条 API  

---

## 4. Won’t

- Redis / Celery / MinIO（默认不纳入；若 Job 堆积严重再单独立项）  
- OCR、Rerank、Hybrid Search  
- 完整 CD 自动部署  
- 完整系统管理后台（组织/角色/菜单全套）  

---

## 5. 退出标准（草案）

```text
□ 上传/删文档/改成员后 audit_log 有对应记录
□ ADMIN 可按时间查询审计列表
□ 主路径回归（pytest）仍绿
□ plan 完成说明
```
